# 04 启动方式与资源策略

## 核心规则

启动 `mdrun` 前，先判断可执行文件类型和机器资源，再选择模板；不要把命令写法固定死。

## 运行判断

- 先判断是普通 `gmx` 还是 `gmx_mpi`。
- `gmx_mpi` 不要机械写 `-ntmpi 1`。
- 默认一个模拟任务使用一块 GPU 和约 18 个 CPU 线程，再根据服务器空闲情况调整。
- 判断 GPU 能否使用时，要区分“`gmx` 二进制带 CUDA 支持”和“当前终端真的能看到 GPU 设备”。
- 如果 `gmx mdrun -gpu_id 0` 报 `0 detected device(s)`，优先检查当前执行环境是否可见 `/dev/nvidia*`，不要先怀疑命令模板。

## 适用

- 所有 `mdrun` 启动前
- 单机 GPU 运行
- 多任务调度前

## 为什么

- `gmx` 和 `gmx_mpi` 的并行模型不同，直接套模板容易错。
- `1 GPU + 18 线程` 是当前环境下的默认经验值，但不是死规则。
- 代理沙盒、容器或 IDE 执行层可能屏蔽 GPU 设备；宿主机有 GPU 不等于当前 shell 一定能直接调用。
