# 05 输出完整性与进程完整性

## 核心规则

生产任务既要能跑，也要保证输出文件可信；静默失败和并发双写都应视为严重问题。

## 输出完整性

- 任何生产 `MD` 都必须明确设置 `nstxout-compressed`，否则模拟即使跑完也可能没有可分析轨迹。
- 任何 `mdrun` 之前都先确认目标 `.tpr` 已由 `grompp` 成功生成；若 `mdrun` 报找不到 `topol.tpr` 或 `<deffnm>.tpr`，先回头查 `grompp` 的首个失败原因。

## 进程完整性

- 同一个 `deffnm` 绝不能并发运行两个 `mdrun`。
- 同一个输出前缀只能有一个进程在写文件。
- `mdp` 中的 `tc-grps`、`comm-grps` 等组名必须与 `index.ndx` 中实际组名逐字一致；组名不一致时，根因属于 `grompp` 输入不自洽，不是 `mdrun` 故障。

## 适用

- 所有生产阶段 MD
- 前台转后台
- 续跑
- 多任务管理

## 为什么

- 没有压缩轨迹是典型静默失败：任务看似完成，分析实际无法进行。
- 并发双写会污染 `.log`、`.edr`、`.xtc` 和 `.cpt`，结果不再可信。
- 很多“`mdrun` 找不到 `.tpr`”只是前一步 `grompp` 失败后的连带症状；不先拆开这两步，容易误判。
