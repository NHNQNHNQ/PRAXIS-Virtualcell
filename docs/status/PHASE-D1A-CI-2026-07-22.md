## 3. Root causes

### Python/Linux hash lock

`requirements/dev-py313.lock` had been compiled on macOS arm64. SQLAlchemy
declares `greenlet>=1` only for selected architectures, including Linux x86_64,
so the macOS compile omitted it. On GitHub's Linux x86_64 Python 3.13.14 runner,
pip discovered the unhashed transitive requirement and correctly rejected it in
`--require-hashes` mode. The three Python jobs stopped at environment creation.

Local Linux/amd64 iteration then exposed the same latent issue one layer later:
Streamlit declares `watchdog<7,>=2.1.5` only outside Darwin. Both target-specific
requirements must be present in the shared macOS arm64/Linux x86_64 closure;
fixing only the first GitHub error would have produced another install failure.

### Frontend integration environment

The frontend job installed the lean runtime lock, which intentionally excludes
the optional mechanistic dependency `cobra`. The real bacteria
`b0720 + b1136` growth case routed to `CaseRunner`, then failed closed when Cobra
could not import: the predictor was rejected, no model remained, and the result
correctly returned `abstain=true`. The E2E assertion expected the supported FBA
path, so this was an environment-profile error, not nondeterministic science and
not a reason to weaken the assertion.
