### P0 必修(release blocker 级 — 但 v0.16.1 已 ship,降级为 v0.16.2 patch 候选)

#### P0-1. `scripts/eval_v0160.py` 凭证泄漏(reviewer C 发现)
- **位置**:`eval_v0160.py:356-357` — 测试账号密码直接写在源码(真值已脱敏,见 PRAXIS_EVAL_* env)
- **严重度**:🔴 HIGH — 公开 GitHub repo 凭证暴露
- **修复**:从环境变量读 `PRAXIS_EVAL_EMAIL` / `PRAXIS_EVAL_PASSWORD`,无默认
- **优先级**:**v0.16.2 patch 必修**

#### P0-2. `praxis2/tools/skill_exec.py:270` shlex 引号剥离(reviewer A 发现)
- **位置**:`python {shlex.quote(rel)}/run.py` → 生成 `python 'cell/skills/...'/run.py`
- **问题**:引号在 `/run.py` 前剥离,shell 把 `/run.py` 当独立参数,
  若 rel 含空格/特殊字符,远端 python 调用失败
- **影响**:目前 167 个 skill 路径都无空格,实际不触发;**未来若 brain 路径
  含空格 / Unicode 会断**
- **修复**:`python {shlex.quote(rel + '/run.py')}`
- **优先级**:**v0.16.2 patch 应修**(防御性,低成本)

### P1 应修(下个 patch 周期内)

#### P1-1. `scripts/eval_v0160.py:249` 空 list vacuous truth(reviewer C)
- `all(not te.get("is_error",False) for te in tool_ends)` 当 `tool_ends=[]` 时返 True
- 修复:`all_ok = bool(tool_ends) and all(...)`

#### P1-2. `praxis2/tools/brain_query.py:139` zip strict=False 掩盖数据不一致(reviewer A)
- 若 `result.hits / scores` 长度不匹配,默 silent 丢弃 → 模型收到不完整结果
- 修复:`strict=True` + assert pre-check

#### P1-3. `praxis2/tools/file_read.py:151` 重复 decode(reviewer A)
- `len(raw_bytes.decode('utf-8', errors='replace'))` 重复 decode,line 148 已得 `text`
- 修复:直接 `len(text)`(性能 + 简洁)

#### P1-4. `praxis2/server/app.py` State 对象可变共享(reviewer B)
- SessionPool.get() 返回 mutable State,line 649 直接 append messages
- 若 session_id 在某错误路径破坏 → 锁失效 → 并发污染
- 修复:加 defensive session_id 合法性 check + 可选 deepcopy on put

#### P1-5. `tests/test_tools_skill_exec.py` monkeypatch 污染(reviewer C)
- `test_skill_exec_degrades_when_no_ssh_env` 删除 env,后续测试 setenv 重新设
- 单独跑某测试可能 monkeypatch scope 泄漏
- 修复:每个测试独立 setup/teardown,不跨测试依赖

### P2 后续迭代(等观察期后)

#### P2-1. `praxis2/tools/rmcp_write.py:194-201` mkdir 权限未校验(reviewer A)
- 若 brains_root 是 read-only 挂载 → mkdir 抛 PermissionError → chat-stream 500
- 修复:try-except OSError → return ok=False

#### P2-2. `praxis2/tools/skill_exec.py:288-292` 异常过宽泛(reviewer A)
- `except Exception: pass` 在 proc cleanup 时,可能掩盖进程泄漏
- 修复:`except (OSError, RuntimeError): pass` 仅捕已知异常

#### P2-3. `praxis2/server/app.py` SessionPool 缺监控指标(reviewer B)
- max_size=200 / TTL=3600s 在 staging 流量下未实测,无 hit rate / eviction rate
- 建议:加监控仪表盘(prometheus 或周报)

#### P2-4. `praxis2/server/app.py:62-76` `_resolve_session_id` 缺 logging(reviewer B)
- fallback 触发(异常 client)无日志,无法察觉滥用
- 修复:`logger.warning(f"session_id fallback for user={...}")`

#### P2-5. `tests/test_app_session_id_fallback.py` 缺 whitespace-only 边界(reviewer C)
- 没测 `"   "` 等 strip-only-falsy 情况
- 修复:加 `test_whitespace_only_session_id`

#### P2-6. `tests/test_tools_brain_query.py:49` substring 断言过宽松(reviewer C)
- `assert any("stiffler" in s.lower() for s in stems)` — 若文件名大小写归一变化,
  或返回 stem 来自幻觉数据,断言仍过
- 修复:验 `top_hit["path"]` 或文件大小

#### P2-7. `scripts/eval_v0160.py:245` DOI 正则过敏感(reviewer C)
- 任何 `10.XXXX/...` 都标"需人工核",误伤合法引用;D 等级实际从未自动分配
- 修复:整合 D 检测逻辑到 score function,或移除自动检测做后处理

#### P2-8. cascade failure / 并发测试缺口(reviewer C)
- 没测 brain 目录权限拒绝、symlink loop、binary content-type 拒绝
- 没测 multi-thread 并发查询线程安全 / 同 brain 不同 stem 写并发
- 修复:补充 corner-case + 并发集成测试
