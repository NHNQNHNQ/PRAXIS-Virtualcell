## 4. 部署链测试

### 4.1 双 dist 同步

每次 FE 改动必须 rsync **两份**（v0.15.1 踩坑）：
```bash
rsync -avz --delete --exclude '._*' frontend/dist/ hipeson@10.102.106.40:/home/hipeson/mzy/PRAXIS-2-fe/dist/
rsync -avz --delete --exclude '._*' frontend/dist/ zkyd@10.102.106.53:/home/zkyd/data1/mzy/PRAXIS-2/frontend_dist/
```

**测试**：deploy 后用 `curl -s http://10.102.106.40:8080/ | grep -oE 'assets/index-[A-Za-z0-9_-]+\.[a-z]+'` 与 `dist/assets/` 文件名比对，必须一致。

### 4.2 backend 重启 SOP

`kill master pid → 等 3-4s → 从空启动 → curl /api/info 验版本号`

教训（贯穿 v0.14-v0.15）：
- `pkill -f "gunicorn.*praxis2"` 会把 ssh 包装 bash 也匹配进去导致 SSH session 死亡 → **不能用**
- `awk '/[g]unicorn.*praxis2/ && $3==1 {print $2; exit}'` 偶发拿不到真 master → 直接 `ps -ef | grep "[g]unicorn"` 看眼 → 取 PPID=1 的 → kill
- `kill -HUP` 多文件 deploy 会搞挂 backend（carry #6 教训），多文件 deploy **必须** stop+start

### 4.3 litellm 重启 SOP

LiteLLM 改 yaml/env 必须 stop+start：
```bash
kill <litellm_master_pid>; sleep 3
source ~/praxis2.env && nohup ~/software/miniconda3/envs/praxis2/bin/litellm --config ~/data1/mzy/PRAXIS-2/deploy/litellm_deepseek.yaml --port 4000 --host 127.0.0.1 > /tmp/litellm-...log 2>&1 & disown
sleep 8; curl -s http://localhost:4000/v1/models -H "Authorization: Bearer sk-litellm-prod-..."
```

### 4.4 配置文件管理

**Prod-only 不入 git** 的两份关键文件：
- `.53:~/data1/mzy/PRAXIS-2/deploy/litellm_deepseek.yaml`（含 model_list 配置）
- `.53:~/praxis2.env`（含 DEEPSEEK_API_KEY / PARATERA_API_KEY / DB / Redis URL 等 secrets）

修改这两个文件后**必须**：
1. 在 backup 路径备份原文件（`cp ~/praxis2.env ~/praxis2.env.bak-YYYYMMDD`）
2. 改动通过 git commit message 记录（即使文件本身不入 git）
3. restart 对应进程
