## 关键发现 — server SessionPool 状态泄漏 bug(评测顺手发现)

评测过程中发现:chat-stream payload 不传 `session_id` 字段时,server 默认
用 `"default"`(app.py:528),所有请求命中同一个 SessionPool slot,导致
`State.turn_count` 跨请求累计,超 max_turns=20 后所有 chat 立即返
`final reason: max_turns`,直到 restart gunicorn。

修复:eval 脚本里改 payload `chat_id` → `session_id`(server 看这个字段)。
production-side FE 应该已经正确传 session_id(v0.15.x 起),但任何用 curl
裸调 chat-stream 的脚本(测试 / 监控)都要注意传 session_id 避免触雷。

→ **改进候选 v0.16.x patch**:server-side 增加 fallback,如果 session_id
缺失就自动 hash(headers+timestamp) 生成 unique session_id,而不是用
固定 "default"。
