## 2. 系统架构

### 后端 `praxis2/`（纯 ASGI，无 FastAPI）
```
core/        执行内核:query()(工具闭环主循环) / state(跨轮状态) / rmcp(相位机) / compact(压缩) / seams(注入缝)
server/      app.py = ASGI 应用(路由+中间件+chat-stream SSE)。单文件较大(~1300 行),是系统中枢
auth/        cookie session 鉴权 + 邮箱注册 + repository(PG)
brains/      13 学科大脑(case/rule/workflow 知识库)+ system_prompt 组装
memory/      session.py = SessionStore(transcript 持久 + resume) ← 本轮 GAP-B-1 主角
store/       存储抽象(base ABC + memory/redis/pg 三后端)。PgStore 多租户 namespace
tools/       工具实现(skill_exec/bash/permission 等)+ 反幻觉检索先行门
hooks/       PreToolUse/PostToolUse/stop_hook(反幻觉 GAP-AH)
runtime/     SessionPool(内存热缓存)/ratelimit/locks/pubsub
llm/         AnthropicClient(走 litellm)
spawn/       后台长任务(>10min)派发
md/          分子动力学 HPC SSH 提交
accounting/  Ledger 计费(balance_li)
agents/      agent spec 路由(13 学科 + general/union/free)
mcp/         MCP client(外部工具接入)
admin/ proposals/ files/ scheduler/  管理/提案/文件/调度
```

### 前端 `frontend/src/`（React + TypeScript + Vite）
```
App.tsx              主组件(~1000 行,对话状态机 + chat-stream 消费 + 渲染)
components/          ConversationSidebar(对话历史) / MessageBubble / SpawnModal / MdModal / 各种 Modal
lib/api.ts           后端 API 封装(chatStream SSE + fetch*)
lib/storage.ts       localStorage 对话缓存
lib/auth.ts          登录态
types/api.ts         类型定义(ChatMessage/Conversation/SSEEvent)
```

### 数据流（一次对话）
```
浏览器 → POST /api/chat-stream {agent,message,model,mode,session_id}
  → app.py:_chat_stream → SessionPool.get(命中复用/miss 则 resume 重建)
  → query() 工具闭环(调 LLM + brain + tools,相位机驱动,反幻觉门)
  → SSE 流式回吐(text_delta/tool_*/final)
  → 每轮持久 transcript 到 PG(SessionStore)
```

## 4. 本轮交付：GAP-B-1 跨会话记忆全栈（v0.18.0 → v0.19.0）

**背景**：智能体每会话从零开始；`SessionStore`（transcript→PG + resume）实现完整但**从未接生产**。GAP-B-1 = 接进 chat 路径，让对话跨重启/换设备/重登持久+恢复。

### 三块（全部 commit + push，走 superpowers brainstorm→spec→plan→subagent-driven TDD）
1. **SP1 后端**（7 task）：`SessionStore` 接 chat 路径。pool miss → `resume()` 重建 State；每轮持久 user/assistant-delta/**纯文本终答**/相位/meta；`GET /api/me/sessions` 列表端点。`_pool` 兜底（无 PG → 纯内存零回归）。
   - **opus final review 抓的反幻觉缺口**：`query.py` 纯文本终答不写 `state.messages`，delta 漏掉 assistant 散文 → 测试 fake 假 append 掩盖了它 → 修（chat 路径显式持久 + fake 忠实 kernel）。
2. **compact-safe delta fix**（单 task）：delta 追踪从位置索引 `_prev_len` 改 **对象身份快照 `{id(m)}`**，抗 reactive compact 对 `state.messages` 的 reassign 截断。
3. **SP2 前端**（3 task，**渐进混合**）：发现前端**从不传 session_id**（SP1 之前从未生效！）→ `conversation.id=session_id` 传 chatStream 激活 SP1 + 启动 `fetchSessions` 并入后端独有会话（lazy stub）+ `onSwitch` 懒填充 + 后端补 `GET /api/me/sessions/{id}`。原「后端权威」重构风险中-高 → 改渐进混合保留现有逻辑。

## 9. 雷区（踩过的坑，务必看）

1. **commit 只 add 目标文件，绝不 `git add .`/`-A`**：工作区常驻无关 stray 文件 `brains/microbiome/{skills/workflows/cooccurrence_network_real/run.py(modified), memory/cases/microbiome-01{4-7}-*, rules/14-*, skills/workflows/{cross_feeding_gem,phage_host_link}}` —— 每次 commit 列具体路径。
2. **`.40`/`.53` 两份独立前端**：部署 SP2 要两边都更新（见 §3）。
3. **SSH `.40` 被 auto-mode classifier 拦**：新 prod host，需用户 settings 加 Bash 白名单 `Bash(ssh:* hipeson@10.102.106.40 *)`。
4. **凭证不入 git**：API key / DB pepper / SMTP 等在 `.53:~/praxis2.env`（不入仓）。e2e 脚本凭证经 env 传。测试账号密码（praxis123456）可公开（本就给学生）。
5. **gunicorn `preload_app=False`** 决定 HUP 能否重载新代码（本项目是 False，故 HUP 有效）。
6. **反幻觉是项目地基**：GAP-AH 做了检索先行门 + stop_hook + ship 门。改 chat 路径/测试时，**测试 fake 必须忠实 kernel contract**（本轮 SP1 就栽在 fake 假 append 掩盖缺陷）。
7. **delicate core** `app.py`/`core/query.py` 深度耦合，改动小心，亲审 diff。
8. ssh 跑 repo 内 python 要 `PYTHONPATH=$PWD`（脚本在 /tmp，sys.path 不含 repo 根）。
