# PRAXIS-2 项目说明

> 系统现状与部署位置。版本 **v0.19.1**,更新日期 2026-06-09。
> 本文只讲「系统是什么、在哪、能干什么」。开发流程与历史决策见 `docs/superpowers/`,逐版本演进见 git tag。

---

## 1. 项目概述

**PRAXIS-2** 是一套自研的 Claude-Code 式 **agent runtime**,面向生物医药科研的 AI 助手平台。

- **形态**:纯 ASGI 后端(不依赖 FastAPI)+ React/Vite 前端,Web 多轮对话界面。
- **内核**:工具闭环主循环(`query()`)+ 相位机(RMCP)+ 压缩(compact)+ 注入缝(seams),即一套自研的 Claude-Code-style harness。
- **领域能力**:13 个学科专家,每个挂真实知识库(案例/规则/技能工作流),真实调用 LLM + 工具链(可 SSH 到远端跑 conda 环境的真实科学计算)。
- **核心特征**:**反幻觉**——智能体不会假称跑过工具或编造结果;检索先行、引用强制真实 DOI、声称执行必须有真实工具调用佐证。

一句话:**把 LLM 从「单次问答」升级为「可审计、不幻觉的科研分析全流程」**。

## 2. 系统架构

### 2.1 后端 `praxis2/`(纯 ASGI,21 个代码模块)

```
core/        执行内核:query()(工具闭环主循环) / state(跨轮状态) / rmcp(相位机) / compact(压缩) / seams(注入缝)
server/      app.py = ASGI 应用(路由 + 中间件 + chat-stream SSE)。单文件 ~1300 行,系统中枢
auth/        cookie session 鉴权 + 邮箱注册 + repository(PG)
brains/      13 学科大脑 + _common 共享规则;case/rule/workflow 知识库 + system_prompt 组装
memory/      session.py = SessionStore(transcript 持久 + resume),跨会话记忆
store/       存储抽象(base ABC + memory/redis/pg 三后端),PgStore 多租户 namespace
tools/       工具实现(skill_exec / bash / permission) + 反幻觉检索先行门
hooks/       PreToolUse / PostToolUse / stop_hook(反幻觉)
runtime/     SessionPool(内存热缓存) / ratelimit / locks / pubsub
llm/         LLMClient(走 litellm,OpenAI format)
mcp/         MCP client(stdio,接外部 MCP server 工具)
spawn/       后台长任务(>10min)派发
md/          分子动力学 HPC SSH 提交
accounting/  Ledger 计费(balance_li)
agents/      agent spec 路由(13 学科 + general/union/free)
admin/ proposals/ files/ scheduler/ skills/ entry/   管理 / 提案 / 文件 / 调度 / 技能 / 入口
```

### 2.2 前端 `frontend/`(React + TypeScript + Vite)

```
App.tsx              主组件(~1000 行):对话状态机 + chat-stream 消费 + 渲染
components/          ConversationSidebar(对话历史) / MessageBubble / BalanceModal / SpawnModal / MdModal 等
lib/api.ts           后端 API 封装(chatStream SSE + fetch*)
lib/storage.ts       localStorage 对话缓存
types/api.ts         类型定义
```

### 2.3 数据流(一次对话)

```
浏览器 → POST /api/chat-stream {agent, message, model, mode, session_id}
  → app.py:_chat_stream → SessionPool.get(命中复用 / miss 则 resume 重建 State)
  → query() 工具闭环(调 LLM + brain 检索 + tools,相位机驱动,反幻觉门)
  → SSE 流式回吐(text_delta / tool_* / final)
  → 每轮持久 transcript 到 PostgreSQL(SessionStore)
```

## 3. 能力现状

### 3.1 智能体(13 学科 + 3 智囊)

| 类别 | 成员 |
|---|---|
| **学科专家** | Cell 细胞 · CRISPR 基因编辑 · Cryo-EM 冷冻电镜 · Dock 对接 · Drug 药物设计 · Enzyme 酶催化 · Immuno 免疫 · MD 分子动力学 · Microbiome 微生物组 · Omics 组学 · Pharma 药代 · Protein 蛋白 · Synth 合成 |
| **智囊模式** | 通用助手(纯 LLM + 公共规则) · 一统大脑(关键词路由到最匹配 1 个学科) · 自由模式(多脑命中,只读不写回) |

同一对话可混用多个智能体。三种对话模式:`ask`(问答) / `plan`(规划) / `auto`(规划 + 自动派发后台执行)。

### 3.2 知识库(brain)

- **14 个 brain**:13 学科 + `_common`(全 agent 共享的硬规则,如 `nature_plot` 可复现绘图规范)。
- 每个 brain 挂 **case**(带真实 DOI 的正/负案例) + **rule**(硬约束) + **workflow**(技能工作流,共 **167 个 skill**)。
- **RMCP 治理**:检索命中则注入领域知识;检索为空显式降级 `degraded_to_bare=True`(不静默用错误上下文)。

### 3.3 工具调用

| 工具 | 能力 |
|---|---|
| **SkillExec** | 真执行链:默认 SSH 到远端 brain 主机,`conda activate <env>` 跑 `python run.py`,返回真实 stdout(JSON);环境不可用时诚实降级,不伪造 |
| **BrainQuery** | 检索学科知识库(case/rule/skill),反幻觉 grounding 来源 |
| **FileRead / WebFetch** | 读文件 / 抓网页 |
| **AgentTool** | fork 子智能体(身份/上下文/token 三层隔离) |
| **RMCPWriteCase** | 写回新案例(强制 ≥1 真实 DOI) |
| **MCP client** | stdio 接外部 MCP server 工具(`mcp__<server>__<tool>`) |
| **BashTool** | 软沙盒跑 shell(白/黑/灰名单),叠加真隔离三件套(opt-in) |

### 3.4 反幻觉(项目地基)

- **检索先行门**:调用 skill / 写 case 前必须先 BrainQuery,否则被门拦截要求补检索。
- **stop_hook**:声称执行了某动作但本轮零成功 tool_use → 否决(veto),防止假称跑过。
- **ship 前门**(`scripts/ship_gate.py`):发版前跑全量 pytest + 反幻觉 KPI(best-of-2),任一不达线非零退出。
- **引用真实**:案例/文献引用强制真实 DOI,不可杜撰。

实测表现:诱导对接智能体编造结合能,它会先检索 → 识别科学陷阱(如共价抑制剂不适用 plain Vina)→ 拒绝给假数值 → 引真实案例 + 文献 → 诚实询问输入,而非编造。

### 3.5 跨会话记忆

- `SessionStore`(transcript → PostgreSQL + `resume`):对话跨重启 / 换设备 / 重新登录都能持久并恢复。
- `SessionPool`(内存热缓存,LRU) + `SessionStore`(权威持久层);pool miss 时从 PG resume 重建状态。
- 端点:`GET /api/me/sessions`(会话列表) + `GET /api/me/sessions/{id}`(单会话历史)。

### 3.6 真隔离(BashTool,opt-in 正交叠加)

| 维度 | 机制 |
|---|---|
| 文件系统 | `unshare --user --map-root-user --mount` + tmpfs 遮蔽(rootless,fail-closed) |
| 资源 | `systemd-run --user --scope -p MemoryMax/CPUQuota`(覆盖整棵进程树,fail-open 降级 rlimit) |
| 网络 | `unshare --net` 空 netns(egress 全封,fail-closed) |

### 3.7 计费

- **Ledger**(`balance_li`,用户表字段,**1 元 = 100 li**):注册赠送 / 充值 / LLM 消耗 / 调用冻结 / 退还 流水。
- 按输入 / 输出 token 计价,余额端点 `GET /api/me/balance` 返回余额 + 最近流水。

### 3.8 工程质量

- **175 个测试文件 / ~2100 用例**。
- 严格走 **superpowers 流程**:brainstorm → spec → 写计划 → subagent-driven TDD(每 task 红→绿→commit + 两阶段 review + opus final review)。
- main 分支即生产线(无 feature 分支约定),核心文件改动 controller 亲审 diff。

## 4. 服务器部署位置

### 4.1 拓扑

```
浏览器 → .40:8080 (反代 / 前端)  ──反代 /api──→  .53:8001 (gunicorn ASGI)  →  litellm 127.0.0.1:4000 → DeepSeek / AWS
              │                                       │
        serve 自己本地的                          serve frontend_dist(same-origin)
        前端 dist(独立一份)                      + PostgreSQL(会话/用户/计费/transcript)
```

⚠️ **`.40` 和 `.53` 各有一份独立前端**:`.53` 的 gunicorn 用 `PRAXIS_STATIC_ROOT` serve SPA(API + FE 同源);`.40` 是反向代理,把 `/api` 转给 `.53`,但 `/`(前端)serve 它**本地的** dist。**部署前端要两边都更新**。

### 4.2 `.53`(`10.102.106.53`,用户 `zkyd`)— 后端主机

| 项 | 位置 |
|---|---|
| 后端进程 | gunicorn ASGI,监听 `127.0.0.1:8001`(对外经 `.40` 反代),`preload_app=False` |
| 代码仓库 | `~/data1/mzy/PRAXIS-2`(即 `/home/zkyd/data1/mzy/PRAXIS-2`) |
| 前端静态根 | `/home/zkyd/data1/mzy/PRAXIS-2/frontend_dist`(gunicorn same-origin serve) |
| conda 环境 | `~/software/miniconda3/envs/praxis2/bin/{python,gunicorn}` |
| LLM 网关 | litellm `127.0.0.1:4000`(上游 DeepSeek `deepseek-v4-pro` / AWS `aws-gpt-5.4`) |
| 数据库 | PostgreSQL(会话 transcript、用户、计费 ledger、多租户 namespace) |
| 凭证 | `~/praxis2.env`(LLM API key、DB pepper、SMTP 等,**不入 git**) |
| 重载 | `kill -HUP <gunicorn master>`(preload_app=False,故 HUP 重载 worker 生效) |

| 项 | 位置 |

### 4.4 部署 SOP

**后端**(改 `.py`):
```bash
rsync -az praxis2/<改的文件> zkyd@10.102.106.53:~/data1/mzy/PRAXIS-2/praxis2/<同路径>
ssh zkyd@.53 "cd ~/data1/mzy/PRAXIS-2 && md5sum <文件> && source ~/praxis2.env && PYTHONPATH=\$PWD python -c 'from praxis2.server.app import make_app_default'"  # md5 验 + import 自检
ssh zkyd@.53 "MASTER=\$(ps -ef|grep '[g]unicorn'|awk '\$3==1{print \$2}'|head -1); kill -HUP \$MASTER"  # reload
curl -s http://10.102.106.53:8001/api/info  # 健康(期望 200 + version)
```

**前端**(改 `frontend/`):
```bash
cd frontend && npm run build                                   # 产物 dist/
rsync -az --exclude='._*' --delete frontend/dist/ zkyd@10.102.106.53:/home/zkyd/data1/mzy/PRAXIS-2/frontend_dist/   # .53
rsync -az --exclude='._*' --delete frontend/dist/ hipeson@10.102.106.40:/home/hipeson/mzy/PRAXIS-2-fe/dist/         # .40 入口
```

## 5. 版本体系

三条 tag 线并存(`git tag -l | sort -V`):

- **`v0.x`** — 后端功能主线。到 v0.16(MCP client + 本地 BashTool)→ v0.17(GA)→ v0.18(真隔离三件套:文件/资源/网络)→ v0.19(GAP-B-1 跨会话记忆全栈)→ **`v0.19.1`(当前)**。
- **`v1.x-学科`** — 13 个 brain milestone(`v1.2-dock` … `v1.13-md`)。
- **`v2.0.x`** — agents 元数据 + synth brain。

> `v0.x` git tag 是项目版本权威。前后端 `/api/info` 的 version 字符串随主线 tag 同步维护。
